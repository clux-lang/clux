# bootstrap/design/ — 设计文档规范与索引

## 写作规范

每篇子设计文档**必须**包含下列小节，缺一不可：

1. **范围**：本文负责哪一层/哪个子系统，明确不负责什么。
2. **输入 / 输出契约**：类型级描述（用 clux 的 `struct`/`tag union` 表达），以及"不变量"。
3. **数据结构**：核心类型定义（ADT 优先），ID/arena 所有权。
4. **错误契约**：会产生哪些诊断（`DiagCode` 列表），各自的 span 指向；错误恢复策略。
5. **与规范对应**：白皮书章节号逐条列出（哪条落在哪个函数/表）。
6. **测试用例清单**：本层要覆盖的用例，能落到 `conformance/` 的写明；不能的（内部结构）写明 golden 形式。
7. **开放问题**：尚未决定的分歧点，标注"暂定 + 需要谁拍板"。

文档编号即实现顺序；未写完的设计不进入实现。

## 与规范文档的边界

`docs/whitepaper/` 只写**语言应当是什么样**（规范）；本目录只写**这个编译器怎么实现**。
两边不互相引用细节：设计文档引用章节号，规范不描述实现。
