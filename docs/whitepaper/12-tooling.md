# 12. 工具链与格式

## 12.1 源文件与包

- 源文件扩展名：`.cx`。
- 包由 `clux.mod` 描述。
- 包根目录是包含 `clux.mod` 的目录。
- 源文件路径可以省略 `.cx` 扩展名；导入解析时自动补全。

## 12.2 命令

```sh
clux run [<file.cx> | <subpkg>]
clux build <file.cx>
clux test [<file.cx>]
clux format [<file.cx>]
clux version
clux eval <expr>
```

- `clux run` 执行程序；有 `clux.mod` 时可以从入口查找。
- `clux build` 生成目标平台可执行文件。
- `clux test` 执行测试。
- `clux format` 格式化源码。
- `clux eval` 在编译期求值表达式。
- `clux bc` 是字节码调试/分发工具，不属于语言主路径。

## 12.3 格式化目标

`clux format` 必须满足：

- 不改变程序语义；
- 保留所有声明；
- 保留 `export` / `import` / `union` / `cunion` / `struct` / `enum` / `type` 等声明；
- 保留注释及注释归属；
- 幂等：对格式化结果再次格式化，输出逐字节一致。

## 12.4 缩进与空白

- 缩进统一 4 个空格，不使用制表符。
- 非空块：

```clux
{
    stmt;
}
```

- 空块写作 `{}`。
- `} else` 写在同一行。
- 二元运算符两侧各一个空格。
- 一元运算符紧贴操作数。
- 函数调用和泛型实例化的 `(` 紧贴 callee：

```clux
foo()
Vec[i32]::new()
```

- 控制流关键字与 `(` 之间有一个空格：

```clux
if (cond)
while (cond)
for (...)
foreach (...)
switch (...)
```

## 12.5 分号与逗号

- 语句以 `;` 结束。
- `;` 后换行。
- `for (...)` 内部的 `;` 不换行。
- 逗号后一个空格，不换行。
- 尾随逗号允许出现在构造和多行参数列表。

## 12.6 数字后缀

数字与类型后缀必须紧贴：

```clux
7i8
3.14f32
42usize
```

格式化不得插入空格。

## 12.7 注释

- 行注释 `//` 到行尾。
- 块注释 `/* ... */`。
- 注释原样保留。
- 行内注释保留在其所属语句的行尾。
- 独立注释按当前缩进输出。

## 12.8 格式稳定性

格式化的输出必须是规范形式；不依赖原始空白、缩进或制表符。
