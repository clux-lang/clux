# clux 语言白皮书

clux 是一门静态类型、编译期可计算、显式所有权、无 GC 的系统级语言。
本白皮书规定源语言的**应然语义**；具体后端如何生成代码不在规范范围内。

## 1. 设计目标

- 显式类型与显式所有权，不依赖隐式生命周期推断。
- 编译期计算（comptime）是语言的一等能力。
- 泛型在编译期单态化，运行期没有类型擦除。
- 与 C ABI 可显式互操作。
- 语法保持统一：类型、值、表达式使用同一套前导类型语法。
- 标准库与用户代码使用同一种语言能力，不依赖隐藏的运行时反射。

## 2. 翻译单元

- 源文件扩展名是 `.cx`。
- 一个 `.cx` 文件是一个翻译单元。
- 翻译单元由顶层声明组成：导入、类型定义、函数、变量、测试。
- 包由 `clux.mod`（JSON）描述；包的入口和子包在清单中声明。

## 3. 编译模型

```text
源文件 .cx
  → 词法 / 语法
  → 前脱糖（语法糖展开）
  → 语义分析、类型检查、泛型单态化、comptime 求值
  → 后端代码生成
  → 可执行程序 / 测试运行器
```

以下内容属于实现细节，不是语言契约：

- 编译器使用字节码还是 C；
- 中间表示的指令集合；
- 编译阶段如何编号；
- 垃圾回收或内存池策略。

## 5. 术语

- **类型表达式**：出现在类型位置或值位置、求值为类型的表达式。
- **值表达式**：求值为值的表达式。
- **编译期值**：在编译阶段可以完全求值的值。
- **接收者**：方法的第一个参数。
- **槽位**：变量、字段、数组元素、参数等可存储值的位置。
- **实例化**：为泛型参数绑定具体类型或值，并生成具体实体。
- **单态化**：每个具体实例生成独立代码，不在运行期保留类型参数。

## 6. 规范性约定

- 所有语法示例都使用规范写法；`clux format` 应当把等价源码整理为同一形式。
- 错误示例只用于说明禁止的结构，不作为可编译代码。
- “必须”规则由语义分析或运行期检查保证；实现可以选择诊断时机，但不得接受
  违反规则的合法程序。
